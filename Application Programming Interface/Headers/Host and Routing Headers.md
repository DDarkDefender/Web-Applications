## Host

#### Vulnerability to check
Host Header Injection Vulnerability
- Password Reset Poisoning
- Web Cache Poisoning
- Open Redirect
- Email Link Manipulation

#### Impact
Host header can influence absolute URLs generated by the application, leading to:
- Manipulated password reset links
- Manipulated cached responses
- Manipulated Redirect destinations
- Links included in emails
- Canonical URLs and other metadata

It can also cause authentication and access-control issues.
- Authentication logic dependent on hostname.
- Administrative functionality restricted by hostname.
- Tenant isolation dependent on hostname.
- Trusted-domain validation bypass.
- Hostname-based security middleware bypass.

#### Cause
Request contains Host header and the path. The server uses this Host value to generate absolute URLs, such as :
```
https://example.com/reset-password
```

> [!NOTE]
> The HTTP Host header and the server's IP address are two different things. Changing the Host header does not necessarily change which server receives the request.
>
> DNS resolution happens when you type a website, once the client establishes a connection it connects to the server IP. You can then manipulate the request to send different Host header to the same IP (vulnerable server).

If the server doesn't validate the Host header properly, the application ends up generating URLs using an untrusted domain.

## X-Forwarded-Host
The X-Forwarded-Host HTTP request header can influence how an application identifies the original hostname of a request.
It is commonly added by reverse proxies, load balancers, and CDN infrastructure.

> [!NOTE]
> All checks for the Host header can be checked for the X-Forwarded-Host


#### Vulnerabilities to check
- Forwarded-header trust bypass
- Proxy/backend hostname inconsistencies
- Reverse-proxy routing manipulation
- SSRF through forwarded hostname
- Multi-header parsing inconsistencies
- Multi-tenant and domain-based routing manipulation
